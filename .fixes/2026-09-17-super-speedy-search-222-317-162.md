# Search 5.76.0: issues 222, 317 and 162

Source commit: `263240b` on Search master. These are code changes, not a deployment or
customer release. Do not claim availability through the update server from this report.

## #222: fixed in code

Both contextual help links returned the obsolete `/knowledgebase/enabled/` URL (HTTP 404).
`assets/js/context-help.js` now uses the existing Developer Reference and Uninstalling
Super Speedy Search guides. `sss_admin::sss_admin_scripts()` versions the asset with the
plugin version. Both destination URLs returned 200 and both links opened through the actual
Plugins > Search Settings > Advanced tooltips in Chromium. The browser assertion failed on
the old rendered URL and passes with the fix.

Customer changelog: 5.76.0, "Fixed settings help links for wp-config.php overrides and data deletion."

## #317: fixed in code

Reproduced with External Images 3.43.9, import-time attachment creation off and Fast Ajax
omitting EI. A fresh product with a plain URL in `_external_image_url` returned an empty image
src, while expanded image metadata worked. `sss_get_json_Posts()` now accepts both supported
representations and escapes the URL. No attachment or extra plugin loading is required.

The cold-request assertion failed before the fix. Chromium checks now pass for normal REST,
Fast Ajax without EI selected and Fast Ajax with EI selected, including actual decoded images
in the shortcode dropdown. Expanded metadata, local attachments and configured default images
are regression controls. Custom templates retain their own rendering behaviour.

Customer changelog: 5.76.0, "Fixed missing external images in Ajax search results before visiting the product page."

## #162: partially resolved; keep open

The actual WooCommerce HPOS Orders screen uses MATCH against the Search orders index, and
EXPLAIN confirms FULLTEXT access for a customer-name search. The old native LIKE query is not
used for that search. However, a saved transaction ID is missing from the order's search
document and the same screen returns no result for it. The original issue includes transaction
IDs, so closing the issue as fully resolved would be premature. No transaction-ID fix is
included in this commit.
